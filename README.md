# Office Desk & Gear

Мобильное приложение KivyMD 2.0 и FastAPI с PostgreSQL. Сотрудник бронирует места, просматривает технику и создаёт обращения с фотографиями. Офис-менеджер управляет столами, бронями и аналитикой; IT-администратор — техникой, назначениями, ролями и обращениями. Интерфейс использует тёмный стиль исходного окна регистрации.

Вход сохраняется после закрытия приложения. Подписанный JWT действует 30 дней по умолчанию; сервер хранит его хеш для отзыва при выходе и смене пароля. Локальный кэш позволяет читать ранее загруженные данные без сети. Все изменения подтверждаются сервером.

## Быстрый запуск на Windows

Нужны Python 3.12 и PostgreSQL 18. Команды выполняются из корня проекта.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` задайте `DATABASE_URL` и `PGPASSWORD`. База должна существовать; таблицы создаются миграциями. Например, в PostgreSQL:

```sql
CREATE DATABASE office_desk_gear;
```

Для новой пустой базы:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Для базы старой версии, содержащей девять исходных таблиц без Alembic:

```powershell
.\.venv\Scripts\python.exe scripts/database.py adopt-legacy
```

Эта команда проверяет исходную структуру, создаёт `pg_dump` в `db_backup/`, отмечает исходную миграцию и обновляет схему в одной транзакции. Связи характеристик переносятся из JSON в `desk_feature_links`; дублирующий список броней заменяется связью с таблицей `bookings`. Неизвестная структура или некорректные старые данные останавливают миграцию. Для уже обновлённой базы используйте обычный `alembic upgrade head`.

Создайте первого администратора с вводом пароля в терминале:

```powershell
.\.venv\Scripts\python.exe -m server.cli create-admin --email admin@company.ru --name "IT Administrator"
```

При регистрации поле «Должность» содержит выпадающий список: «Сотрудник», «Офис-менеджер», «IT-администратор». Выбор сохраняется в профиле и сразу задаёт соответствующую роль и права аккаунта после подтверждения почты. Администратор также может менять роли в приложении или командой:

```powershell
.\.venv\Scripts\python.exe -m server.cli set-role --email manager@company.ru --role office_manager
```

Для локальной демонстрации можно загрузить связанные начальные данные:

```powershell
.\.venv\Scripts\python.exe -m server.cli seed-demo
```

Только в development создаются `employee@company.ru`, `it@company.ru`, `office@company.ru` с паролем `password123`. На рабочем сервере демонстрационное заполнение запрещено.

```powershell
.\.venv\Scripts\python.exe main.py
```

Локальный запуск открывает клиент и собственный API. Если адрес API уже сохранён в настройках клиента, используется это подключение без запуска дополнительного сервера. При закрытии клиента его собственный API останавливается; уже запущенный чужой процесс API повторно используется и остаётся работать.

Сервер и клиент можно запустить отдельно:

```powershell
.\.venv\Scripts\python.exe run_app.py
# В другом терминале:
$env:ODG_CLIENT_ONLY = '1'
.\.venv\Scripts\python.exe main.py
```

Swagger: <http://127.0.0.1:8000/docs>. Проверка процесса: `/health`; проверка PostgreSQL и версии миграции: `/health/ready`. Маршруты приложения имеют префикс `/api/v1`.

## Удалённый сервер с HTTPS

На Linux-сервере нужны Docker и Compose, доменное имя с DNS на сервер и входящие порты 80/443. Скопируйте проект и `.env.example` как `.env`; задайте:

- `DOMAIN` — ваш домен без протокола;
- `POSTGRES_PASSWORD` — случайный пароль в hex, чтобы он был допустим внутри URL;
- `JWT_SECRET` — независимая случайная строка длиной не менее 32 символов;
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` — работающий почтовый сервер.

Случайное значение можно получить командой `python -c "import secrets; print(secrets.token_hex(32))"`. Секреты нельзя сохранять в Git или включать в APK.

```bash
docker compose up -d --build
docker compose exec api python -m server.cli create-admin --email admin@company.ru --name 'IT Administrator'
docker compose logs --tail=100 api
```

Compose запускает PostgreSQL с постоянным томом, API под непривилегированным пользователем и Caddy с TLS. PostgreSQL доступен только внутренней сети контейнеров, служебный порт API привязан к `127.0.0.1`. Перед API автоматически выполняются миграции с блокировкой от параллельного DDL. Том `api_data` сохраняет вложения. Для внешней PostgreSQL измените `DATABASE_URL` сервиса API, используйте TLS-параметры провайдера и исключите локальный сервис `db` из своего deployment.

В production включено подтверждение почты. SMTP должен принимать STARTTLS на указанном порту; `SMTP_STARTTLS=0` предназначен для доверенного локального relay. В development `MAIL_MODE=outbox` сохраняет письма в `server/data/outbox/` для проверки без отправки. Для полного сценария подтверждения установите `REQUIRE_EMAIL_VERIFICATION=1` и локально.

## Android

Целевая платформа — Android 10 и новее, ARM64. Приложение на телефоне запускает только клиент; API и PostgreSQL работают на сервере. На экране входа откройте настройки и сохраните `https://ваш-домен/api/v1`. Адрес `127.0.0.1` на телефоне обозначает сам телефон. Удалённое подключение требует HTTPS с действительным сертификатом.

В репозитории есть `buildozer.spec` и отдельный workflow **Android APK**, запускаемый вручную из вкладки Actions. Результат успешной сборки — APK в артефакте `OfficeDeskGear-android-debug`. Сборка не запускается автоматически при каждом коммите.

Для локальной сборки нужны Linux/WSL2, Python 3.11 на хосте, Java 17 и системные зависимости из `docs/ANDROID.md`. Скопируйте проект в файловую систему Linux в путь без пробелов, создайте отдельное окружение и выполните:

```bash
python3.11 -m venv .buildenv
source .buildenv/bin/activate
pip install 'git+https://github.com/kivy/buildozer.git@76bac28545c66bbcc671d49aca553a747d69608e' setuptools wheel cython==0.29.34
buildozer -v android debug
```

Сборка использует зафиксированный p4a develop, целевой Python 3.14.2 и локальный рецепт Material You 3.0.4. Это требуется для нативных зависимостей KivyMD 2.0; точные версии и первичные источники указаны в `docs/ANDROID.md`. APK появится в `bin/` после успешной сборки. Его можно установить на телефон вручную или через `adb install -r bin/имя.apk`. Для публикации в магазине отдельно нужны подписанный release, ключ владельца и требования магазина. iOS-сборка в данный комплект не входит.

Камера запрашивает разрешение при использовании и освобождается при уходе с экрана или сворачивании. При недоступности камеры ID оборудования можно ввести вручную. Фотография выбирается через системный интерфейс, QR и отчёт отправляются через системное меню, включая доступные приложения печати.

## Сессии, кэш и время

- На Android bearer шифруется ключом Android Keystore, на Windows используется DPAPI. Пароль не сохраняется. Ключ подписи JWT на сервере переживает перезапуски; в production он задаётся через окружение.
- Кэш записывается атомарно в приватный каталог приложения, содержит время загрузки и ограничен 80 записями сроком семь дней и общим размером 6 МиБ. Один ответ более 2 МиБ не сохраняется в кэш. Медиа хранятся отдельно с ограничением количества и объёма. Выход или смена сервера очищают персональный кэш и локальный токен; обычное закрытие приложения их сохраняет.
- Один фоновый worker и ограниченная очередь выполняют HTTP вне потока Kivy. Ответы закрываются, пул HTTP освобождается при паузе/остановке; активный запрос завершает закрытие пула после чтения ответа. Запоздалые callbacks не обновляют другой аккаунт.
- FastAPI выдаёт ORM Session на запрос через `Depends`. По завершении Session закрывается, при исключении транзакция откатывается; пул PostgreSQL ограничен. Аутентификационная сессия является записью БД и не держит открытое соединение между запросами.
- Время офиса задаёт `OFFICE_TIMEZONE`, по умолчанию `Europe/Moscow`. Даты со смещением переводятся в этот пояс; даты без смещения считаются временем офиса. Ответ API возвращает время офиса без смещения. Сроки JWT и одноразовых кодов считаются по UTC.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
.\.venv\Scripts\python.exe tests/benchmark.py
```

Интеграционные проверки используют настоящую PostgreSQL и отдельную уникальную схему, создают её миграциями, проверяют ограничения самой БД и удаляют только свою схему в `finally`. Недоступная настроенная PostgreSQL считается ошибкой. Benchmark проверяет локальный профиль нагрузки, а не гарантирует характеристики удалённого хоста.

Трассировка 25 сценариев Vision и шести кейсов находится в `docs/REQUIREMENTS.md`, результаты доступных проверок и ограничения окружения — в `docs/TEST_REPORT.md`. Старый отчёт от 27 октября не подтверждает текущую версию.

## Резервные копии

```powershell
.\.venv\Scripts\python.exe scripts/database.py backup
.\.venv\Scripts\python.exe scripts/database.py verify-restore db_backup/имя.dump
```

Проверка восстановления требует PostgreSQL-права создания БД, создаёт отдельную `odg_restore_*`, проверяет таблицы и внешние связи и удаляет только эту временную БД. Для рабочего сервера сохраняйте резервные копии БД и тома вложений на отдельном носителе. Не выполняйте `docker compose down -v`, если данные нужно сохранить.

## Структура

`client/app.py` содержит представления KivyMD, `client/viewmodels/` — управление состоянием команд, `client/services/` — REST-клиент, `client/core/` — приватное хранилище и ресурсы устройства. На сервере HTTP-маршруты находятся в `server/api/`, бизнес-правила в `services/`, ORM-запросы в `repositories/`, декларативные таблицы в `models/`, DTO и входные/выходные схемы отдельно, Session и конфигурация — в `database/` и `core/`. Версии схемы PostgreSQL находятся в `migrations/versions/`.

Основные связи 1:N: пользователь → брони, стол → брони, оборудование → обращения. Связь N:M столов и характеристик нормализована через `desk_feature_links` с составным первичным ключом. Брони и обращения сохраняют историю: связанные с ними пользователи/места/устройства защищены FK от удаления; временные коды и сессии удаляются `CASCADE`, связь характеристики — `RESTRICT`, связи стола с характеристиками — `CASCADE`. Индексы покрывают email, серийный/инвентарный номер, FK, даты броней и срок сессий; индекс обратного направления N:M поддерживает поиск по характеристике.
