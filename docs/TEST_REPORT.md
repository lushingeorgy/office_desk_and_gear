Итого 52 автоматические проверки: 32 сценария настоящей PostgreSQL, 13 клиентских, 3 проверки запуска и 4 SMTP. Отдельно выполнены 72 desktop UI-этапа, включая выбор должности из списка, сохранение роли и обновление карты после конфликта брони. Нативные изменения Android проверяются отдельно на устройстве.

Автоматические сценарии API проверяют дубликаты и значения полей, отсутствие утечки пароля в ошибках, подпись и срок JWT, отзыв при выходе/сбросе, роли и принадлежность, CRUD и повторное чтение из новой Session, серверные поиск/фильтрацию/сортировку/страницы, нормализованную N:M, ограничения БД и rollback, одновременную бронь с единственным победителем, изменение/частичный период/ночной интервал, обезличенное расписание, фото/историю/комментарии/уведомления и сохранённые отчёты. Новые сценарии 03b/03c подтверждают сохранение каждой выбранной роли, повторный вход, фактические права создания столов и техники, отказ для недопустимых ролей в API/прямом вызове сервиса и невозможность смены роли через профиль. Административные тестовые аккаунты создаются через обычную регистрацию, без подмены роли в БД.

Скрипт `tests/check_api.py` перенаправлен на актуальную приёмку. Старые результаты от 27 октября относятся к прежнему контракту и не используются для подтверждения этой версии.

## Производительность

Локальный FastAPI TestClient вызывает приложение `server.main` с настоящей PostgreSQL. В тестовой схеме 100 пользователей, 50 столов, 200 устройств, 1500 броней и 200 обращений; десять параллельных клиентов. Это измерение приложения и локальной БД, без сети телефона и внешнего TLS.

| Операция | Запросов | p95 | Цель SAD |
|---|---:|---:|---:|
| Поиск столов | 1000 | 161 мс | ≤ 1000 мс |
| История броней | 1000 | 117 мс | ≤ 1000 мс |
| Создание брони | 40 | 165 мс | ≤ 2000 мс |
| Создание обращения | 40 | 116 мс | ≤ 2000 мс |
| Аналитика за 30 дней | 30 | 106 мс | ≤ 3000 мс |

Ошибок HTTP нет. Занятых соединений после прогона — ноль. Подробные локальные результаты сохраняются в игнорируемом `tests/artifacts/benchmark_latest.json`; они не являются гарантией производительности произвольного удалённого сервера.

## Android и удалённое окружение

Итоговый ARM64 debug APK соответствует коммиту `72fba2bf3e8c5c8efd3f504860205dcb0892b1c2`. [Android CI 41187885019](https://github.com/lushingeorgy/office_desk_and_gear/actions/runs/41187885019) полностью успешен: сборка, выравнивание для 16 KiB, подпись и **13/13 runtime-проверок**. Официальный `apksigner` и сертификаты v2/v3 подтвердили один сохранённый тестовый ключ. SHA-256 сертификата: `7c089228a4b32e5da32971ca8970b8e7b9e2c006355131eab1b34439b82370d0`; SHA-256 APK: `d1958b4ca3863f582ccfcbdb043aeff54dddb0fa4930db6c7fba03745e03dbc4`. Удобная локальная копия: `bin/OfficeDeskGear-1.1.0-72fba2b.apk`, рядом файл SHA-256. Ключ подписи в APK/репозиторий не включён.

Runtime запускает настоящий подписанный ARM64 APK на Google APIs Android 15 / API 35 x86_64 с ARM-трансляцией. Проверены касание выпадающей должности и живой PID, сохранение адреса API, вход, Android Keystore без открытого JWT, одна серверная сессия, кэш главной, тот же пользователь и credential после force-stop/restart без нового входа, очистка данных и отзыв сессии при явном выходе. Доказательства: `tests/artifacts/android-ci-72fba2b/runtime/result.json`, screenshots/logcat и официальный signing report; в CI — артефакты `OfficeDeskGear-android-runtime` и `OfficeDeskGear-apk-signing`.

[Backend CI того же коммита](https://github.com/lushingeorgy/office_desk_and_gear/actions/runs/41187885068) прошёл на чистой Ubuntu 24.04: **32 проверки PostgreSQL и 20 остальных проверок**, сборка Docker-образа, миграции пустой БД и HTTP readiness запущенного контейнера. Тестовый контейнер удалён.

Обезличенные локальные результаты: `tests/artifacts/physical-phone/result.json` (15 checks), `gallery-result.json`, `camera-result.json` и снимки тестовых экранов. Временная схема PostgreSQL удалена после штатного завершения API; тестовый файл Downloads и приватные серверные вложения удалены. ADB-сервис, запущенный для проверки, остановлен. Экспортированные пользователем изображения относятся к системному хранилищу, а очистка logout относится к приватному кэшу приложения.

Внешний сервер, домен и корпоративный SMTP не настраивались: запрос требует готовности backend к размещению. Docker Compose, Caddy HTTPS и инструкция настройки подготовлены; адрес HTTPS задаётся в приложении. Протокол SMTP, MIME и проверка TLS подтверждены локальными тестами; доступность конкретного будущего хоста и доставка через его SMTP проверяются при настройке окружения. Бумажное задание на физический принтер не отправлялось.

## Повторение

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
.\.venv\Scripts\python.exe tests/benchmark.py
```

UI smoke запускается отдельно с установленными клиентскими зависимостями; он открывает реальное окно и использует отдельную тестовую схему. Резервные копии, сообщения с кодами и приватные данные тестов исключены из Git.
