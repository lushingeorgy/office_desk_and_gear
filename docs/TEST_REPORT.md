Итого 51 автоматическая проверка: 31 сценарий настоящей PostgreSQL, 13 клиентских, 3 проверки запуска и 4 SMTP. Отдельно выполнены 72 desktop UI-этапа, включая выбор должности из списка, сохранение роли и обновление карты после конфликта брони. Нативные изменения Android проверяются отдельно на устройстве.

Автоматические сценарии API проверяют дубликаты и значения полей, отсутствие утечки пароля в ошибках, подпись и срок JWT, отзыв при выходе/сбросе, роли и принадлежность, CRUD и повторное чтение из новой Session, серверные поиск/фильтрацию/сортировку/страницы, нормализованную N:M, ограничения БД и rollback, одновременную бронь с единственным победителем, изменение/частичный период/ночной интервал, обезличенное расписание, фото/историю/комментарии/уведомления и сохранённые отчёты. Новые сценарии 03b/03c подтверждают сохранение каждой выбранной роли, повторный вход, фактические права создания столов и техники, отказ для недопустимых ролей в API/прямом вызове сервиса и невозможность смены роли через профиль. Административные тестовые аккаунты создаются через обычную регистрацию, без подмены роли в БД.

Скрипт `tests/check_api.py` перенаправлен на актуальную приёмку. Старые результаты от 27 октября относятся к прежнему контракту и не используются для подтверждения этой версии.

## Производительность

Локальный FastAPI TestClient вызывает приложение `server.main` с настоящей PostgreSQL. В тестовой схеме 100 пользователей, 50 столов, 200 устройств, 1500 броней и 200 обращений; десять параллельных клиентов. Это измерение приложения и локальной БД, без сети телефона и внешнего TLS.

| Операция | Запросов | p95 | Цель SAD |
|---|---:|---:|---:|

| История броней | 1000 | 130 мс | ≤ 1000 мс |

| Создание обращения | 40 | 139 мс | ≤ 2000 мс |

Ошибок HTTP нет. Занятых соединений после прогона — ноль. Подробные локальные результаты сохраняются в игнорируемом `tests/artifacts/benchmark_latest.json`; они не являются гарантией производительности произвольного удалённого сервера.

## Android и удалённое окружение

В [GitHub Actions 41102591536](https://github.com/lushingeorgy/office_desk_and_gear/actions/runs/41102591536) успешно собран ARM64 debug APK для commit `add995994c604ccc8bbaee4c792464fe5490004d`. Артефакт `OfficeDeskGear-android-debug` содержит `officedeskgear-1.1.0-arm64-v8a-debug.apk`. Сборка использует закреплённые Buildozer/p4a, Kivy 2.3.1 / KivyMD 2.0, Python 3.14.2 и нативные зависимости, включая рецепт Material You 3.0.4. Это результат реальной сборки, а не только наличие конфигурации.

На чистом Linux [прогон backend CI](https://github.com/lushingeorgy/office_desk_and_gear/actions/runs/40903105917) прошёл: исходные 40 автоматических проверок, сборка Docker-образа, миграции пустой PostgreSQL и готовность запущенного контейнера. Новые локальные проверки роли увеличили общее число до 51; этот предыдущий Linux-прогон не подтверждает добавленные позднее сценарии.

Runtime-задание того же Android CI на x86_64 Google APIs Android 11 / API 30 завершилось ошибкой до экрана входа: `libndk_translation.so` остановился с SIGILL на корректной ARM64-инструкции `fcvtzu d4, d3` в `_Py_HashDouble` библиотеки `libpython3.14.so`. Снимки экрана и logcat сохранены в артефакте `OfficeDeskGear-android-runtime`. Это подтверждённый сбой ARM-трансляции эмулятора; результат запуска на настоящем ARM-устройстве проверяется отдельно. Для следующего прогона подготовлен Google APIs API 35 и более раннее обнаружение native crash; его успешный результат пока не получен.

30.10.2026 APK commit `add9959` установлен через ADB на физический Samsung SM-S938B: Android 17, SDK 37, ARM64. Установка завершилась `Success`, холодный запуск показал настоящий экран входа KivyMD, процесс продолжил основной цикл без ошибки Python/SIGILL. Обнаружено наложение заголовка на status bar; подготовлено исправление через штатные Android WindowInsets p4a. Это исправление и новый выбор роли ещё требуют пересборки и проверки обновлённого APK.

На физическом устройстве пока не подтверждены Keystore после принудительной остановки, камера/галерея/сканирование, системная отправка и печать. Порядок проверки приведён в `docs/ANDROID.md`; успешный холодный запуск не заменяет эти проверки.

Удалённый сервер не был развёрнут: адрес/доступ к серверу, домен и SMTP не предоставлены. Docker Compose и HTTPS-конфигурация подготовлены. Корпоративная SMTP-доставка проверяется отдельно после настройки; локальные тесты используют приватный outbox.

## Повторение

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
.\.venv\Scripts\python.exe tests/benchmark.py
```

UI smoke запускается отдельно с установленными клиентскими зависимостями; он открывает реальное окно и использует отдельную тестовую схему. Резервные копии, сообщения с кодами и приватные данные тестов исключены из Git.
