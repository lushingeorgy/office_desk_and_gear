## Зафиксированная конфигурация

| Компонент | Значение |
| --- | --- |
| Buildozer | `76bac28545c66bbcc671d49aca553a747d69608e` |
| python-for-android develop | `1c9a4b4f817847bd8505d972d1a0e6f965929a88` |
| Python на телефоне и hostpython | `3.14.2` |
| Kivy и KivyMD | `2.3.1` и `2.0.0` |
| Material You | `3.0.4`, локальный рецепт |
| MaterialShapes и PyCairo | `0.3` и `1.28.0` |
| Системная печать QR | AndroidX `androidx.print:print:1.1.0` |
| Android | arm64, Android 10 и новее, target API 35 |
| NDK | `28c`, native API `24` |
| Хост сборки | Linux, Python 3.11, Java 17 |

Минимальный Android API приложения 29 допускает использование библиотек,
собранных для native API 24. Эти параметры задаются отдельно. Native API 24
совпадает с тегом опубликованного ARM64 wheel Material You для CPython 3.14.
Флаг `p4a.extra_args = --allow-minsdk-ndkapi-mismatch` явно разрешает
упаковщику сочетание native API 24 и минимального API приложения 29;
минимальная поддерживаемая версия Android остаётся 10.

В `buildozer.spec` название записано как `Office Desk &amp; Gear`: зафиксированный
шаблон p4a вставляет его непосредственно в XML-ресурс без экранирования.
Android разбирает `&amp;` как символ `&`, поэтому название в лаунчере остаётся
`Office Desk & Gear`; отображаемое название внутри Kivy также сохраняется.

Обычный рецепт Material You в указанном p4a содержит версию 2.0.10, тогда как
KivyMD 2 требует версию не ниже 3.0.3. Поэтому `p4a-recipes/materialyoucolor`
использует официальный архив 3.0.4 с SHA-256. Стандартный PyProjectRecipe
может установить соответствующий Android wheel либо собрать C++17 из
проверенного исходного архива. PyCairo и libcairo уже представлены рецептами
в выбранном p4a; отдельный рецепт MaterialShapes не нужен.

## Сборка через GitHub Actions

В репозитории GitHub откройте Actions → Android APK →
Run workflow. Файл `.github/workflows/android.yml` устанавливает зависимости,
собирает debug APK и сохраняет его как `OfficeDeskGear-android-debug`.
Само наличие workflow не подтверждает успешной сборки: дождитесь зелёного
результата и скачайте APK из артефактов конкретного запуска.

Ключ нативного кэша вычисляется из требований, NDK/API, архитектуры,
зафиксированного p4a, параметров хоста сборки и содержимого локальных рецептов.
Изменение названия, версии приложения или клиентского Python-кода не сбрасывает
скомпилированные библиотеки; упаковка каждый раз использует актуальные исходники.
Для первого запуска нового ключа предусмотрен перенос успешно сохранённого
кэша `android-v3` только при совпадении известных нативных входных данных.
Смена библиотеки, рецепта или инструментов требует другого ключа и новой сборки.

Debug APK подписывается отдельным тестовым ключом `~/.android/debug.keystore`.
Workflow сохраняет его в development-only кэш до начала сборки и проверяет
наличие сохранённой записи. После Buildozer он явно подписывает итоговый APK
через SDK `apksigner`, проверяет подпись и сравнивает сертификат внутри APK
с сертификатом сохранённого ключа. Только проверенный APK публикуется и
передаётся в `android-runtime`; отчёт сохраняется отдельно в артефакте
`OfficeDeskGear-apk-signing`. В той же области кэша ветки/PR последующие сборки
используют прежний сертификат, чтобы `adb install -r` сохранял данные приложения.
Публичный SHA-256 сертификата выводится в логе; сам ключ не включается в Git
или APK-артефакт. Этот кэш не предназначен для release-ключа. Кэш GitHub может
истечь или быть удалён; для распространяемого релиза нужен отдельный постоянно
сохраняемый защищённый ключ подписи. Перед обновлением APK следует сравнивать
сертификаты: Android не обновляет существующую установку другим ключом.

Для проверенного APK `72fba2b` официальный `apksigner` и сертификаты внутри
v2/v3 signing blocks подтвердили SHA-256 тестового сертификата
`7c089228a4b32e5da32971ca8970b8e7b9e2c006355131eab1b34439b82370d0`.
SHA-256 самого APK:
`d1958b4ca3863f582ccfcbdb043aeff54dddb0fa4930db6c7fba03745e03dbc4`.
Отчёт подписи находится в `OfficeDeskGear-apk-signing` этого запуска CI.

После пользовательской сборки CI создаёт отдельный QA ARM64 APK с другим
package `org.officedeskgear.officedeskgearqa` и названием `Office Desk Gear QA`.
Только перед QA-сборкой адрес заменяется на `http://10.0.2.2:8000/api/v1`.
Пользовательский APK уже подписан и опубликован отдельно до этой замены;
упакованный конфиг проверяется на фиксированный HTTPS-адрес. Задача
`android-runtime` запускает QA APK на Android 15 Google APIs x86_64 с ARM
translation, поднимает временные PostgreSQL и API и проверяет экран входа,
автоматическую привязку к API без настройки, вход,
Android Keystore, кэш, восстановление аккаунта после остановки процесса и выход.
Скриншоты, OCR, свойства образа, logcat и `result.json` сохраняются в артефакт
`OfficeDeskGear-android-runtime`, в том числе при ошибке. Отсутствие ARM64
translation, нативное падение или незавершённый сценарий означают провал проверки.

В запуске `41187885019` пройдены все 13 runtime-проверок реального ARM64 APK:
экран входа, выбор IT-должности настоящим касанием без смены процесса,
настройка API, вход, шифрование credential через Android Keystore, отсутствие
JWT в открытом виде, одна серверная сессия, сохранение home-кэша, восстановление
того же аккаунта и credential после force-stop без повторного входа, очистка
личных данных и отзыв серверной сессии при выходе. Локальные доказательства:
`tests/artifacts/android-ci-72fba2b/runtime/result.json`, скриншоты и logcat.

Используется образ Android 15 Google APIs, объявляющий `arm64-v8a` и
`libndk_translation.so`. Переводчик Android 11 падал на инструкции `FCVTZU`
в CPython `_Py_HashDouble`, поэтому для этого прогона он не используется.
Эмуляторная проверка не заменяет приёмку камеры и системных Android-действий
на физическом телефоне.

## Сборка в Linux

Используйте отдельную копию проекта в пути без пробелов, например
`~/office_desk_gear`. Для WSL нужна Linux-файловая система домашнего каталога,
а не каталог OneDrive или `/mnt/c/...`.

```bash
sudo apt-get update
sudo apt-get install -y build-essential git zip unzip autoconf automake \
  libtool libltdl-dev pkg-config zlib1g-dev libncurses-dev libtinfo6 \
  cmake ninja-build libffi-dev libssl-dev autopoint gettext ccache patch \
  openjdk-17-jdk python3-venv python3-dev
python3.11 -m venv .buildenv
source .buildenv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install \
  'git+https://github.com/kivy/buildozer.git@76bac28545c66bbcc671d49aca553a747d69608e' \
  'Cython==0.29.34'
buildozer -v android debug
```

На хосте должен быть установлен Python 3.11. Версия целевого Python 3.14.2
собирается инструментами p4a независимо от версии хоста. При изменении
нативных зависимостей выполните `buildozer android clean` перед новой сборкой.
Первый запуск скачивает SDK, NDK и исходные архивы; необходимы сеть и свободное
место на диске. OpenCV нужен для распознавания QR и увеличивает время сборки.

## Приёмка на телефоне

В карточке QR предусмотрены отдельные действия «Распечатать QR-код» и
«Сохранить / поделиться». Печать использует системный Android print preview
через AndroidX PrintHelper с масштабом FIT; отправка файла открывает Sharesheet.
Для этого `buildozer.spec` содержит `android.enable_androidx = True` и
`android.gradle_dependencies = androidx.print:print:1.1.0` — стабильную версию
из [официального AndroidX Print](https://developer.android.com/jetpack/androidx/releases/print).
На desktop действие печати открывает изображение в просмотрщике; печать
выбирается пользователем в нём.

Эта реализация добавлена после APK `04edcfc` и пока требует новой сборки и
физической проверки: открыть системное предварительное отображение QR,
проверить изображение и отменить диалог. Открытие Sharesheet само по себе
не подтверждает системную печать; отправка задания на реальный принтер
не требуется для проверки предварительного отображения и отмены.

1. Установите полученный APK через файловый менеджер или `adb install -r bin/OfficeDeskGear-1.1.0-72fba2b.apk`.
2. После размещения API по встроенному адресу проверьте регистрацию, письмо с кодом, вход и восстановление пароля. Ручного ввода адреса в приложении нет.
3. Войдите, закройте приложение, остановите его в настройках Android и откройте снова:
   пользователь должен остаться в аккаунте до истечения или отзыва токена.
4. Отключите сеть и перезапустите клиент: ранее загруженные сведения должны
   показываться с отметкой кэша; изменение данных должно требовать соединения.
5. Включите сеть, создайте, измените и отмените бронь; проверьте конфликт
   одновременного бронирования со второго клиента.
6. Откройте QR-сканер, выдайте доступ к камере, считайте код и выйдите со страницы:
   индикатор использования камеры должен погаснуть. Повторите после сворачивания.
7. Загрузите выбранную фотографию в обращение, измените статус под IT-аккаунтом
   и проверьте уведомление, комментарии и историю у автора.
8. Под IT-аккаунтом создайте технику, назначьте её сотруднику, сохраните QR и
   откройте системное меню передачи файла. Отдельной кнопкой «Распечатать QR-код»
   откройте предварительное отображение печати и отмените его без отправки
   на принтер. Проверьте экспорт отчёта.
9. Нажмите «Выйти», перезапустите приложение и убедитесь, что личный кэш
   предыдущего пользователя недоступен новому аккаунту.

Результаты этой проверки следует записать с моделью телефона, версией Android
и идентификатором сборки. Проверка desktop-интерфейса её не заменяет.
