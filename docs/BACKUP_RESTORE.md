# Проверка восстановления SAD 11.4.7

30 октября 2026 года `tests/backup_restore.py` успешно проверил восстановление текущей схемы PostgreSQL 18.6 и файлов вложений. Проверка использует существующую команду `scripts/database.py backup`, настоящий `pg_dump`/`pg_restore` и FastAPI с настоящей PostgreSQL, без подмены репозиториев.

Скрипт создаёт две новые БД с уникальными именами `odg_backup_src_*` и `odg_backup_dst_*`. В исходной БД выполняются миграции до `0002`, через API создаются три роли, профиль, стол, назначенное устройство, бронь, обращение с фотографией, комментарий и переход статуса. После завершения запросов и закрытия приложения создаются dump БД и отдельный архив `uploads`. Они восстанавливаются в пустую вторую БД и отдельный каталог данных.

Новый процесс приложения читает восстановленные данные с прежним JWT. Полностью сравниваются восемь результатов: профиль, история броней, список и карточка обращения, история обращения, уведомления, назначенное оборудование и SHA-256 фактически полученного через API изображения. Дополнительно проверяются отказ доступа к изображению без авторизации, новая бронь после восстановления последовательностей ID и отсутствие занятых соединений в пуле. Восстановлены 14 прикладных таблиц и версия Alembic `0002`.

Рабочая БД из `.env` не открывается тестом: её параметры подключения используются только для подключения к служебной БД `postgres` и создания изолированных БД. Перед миграциями проверяются фактические `current_database()` и `current_schema()`. В `finally` удаляются только два строго проверенных сгенерированных имени БД и каталог теста внутри `tests/artifacts`. Это выполняется и при ошибке; подключения и subprocess ограничены таймаутами. Dump, архив и временный файл с тестовым токеном также удаляются. В выводе и сохраняемом отчёте нет адресов пользователей, токенов, паролей и DSN.

Запуск из корня проекта требует установленного PostgreSQL client tools и права `CREATE DATABASE` у настроенного пользователя:

```powershell
.\.venv\Scripts\python.exe tests/backup_restore.py
```

Обезличенный результат сохраняется в игнорируемом `tests/artifacts/backup_restore_latest.json`. Отдельный контролируемый сбой перед `pg_restore` подтвердил удаление обеих БД и приватных файлов в ветке ошибки.

Тест подтверждает целостность прикладного восстановления, но не настройку расписания резервного копирования на будущем удалённом сервере. На рабочем сервере dump и том вложений сохраняются на отдельном носителе; для согласованной пары нужно приостановить операции записи приложения на время создания обоих снимков. В тесте исходный процесс полностью остановлен перед копированием. Секрет подписи JWT и конфигурацию сервера следует хранить отдельно от публичного кода и переносить вместе с окружением, чтобы сохранённые сеансы оставались действительны после восстановления.
