# Размещение на общем сервере

Ежедневный бэкап PostgreSQL на сервере настроен на 04:15 МСК, хранятся 14 последних
успешных копий в `/opt/projects/office_desk_gear/backups/`. [Управление и проверка](BACKUPS.md).

Рабочий каталог проекта: `/opt/projects/office_desk_gear`.
Каталог на диске не добавляется в HTTP-адрес автоматически. Настройка общего
прокси определяет внешний URL. На проверенном сервере используется общий Caddy
и домен `v3294121.hosted-by-vdsina.ru`; отдельный префикс проекта —
`/office-desk-gear`. Соседнее приложение находится в `/opt/projects/maskarad`.

`compose.shared.yaml` запускает только PostgreSQL и API в отдельном Compose
проекте. Он не занимает 80/443 и не изменяет соседние проекты. Порт API
`127.0.0.1:8011` проверен свободным; перед следующим размещением повторить `ss -ltn`.
Порт PostgreSQL наружу не публикуется. Данные живут в отдельных постоянных томах.

## Подготовка

1. Убедиться, что Docker Compose уже доступен и каталог/порт выделены этому проекту.
2. Скопировать `.env.server.example` в корень проекта как `.env.server`, выставить
   `chmod 600 .env.server`, задать независимые случайные `POSTGRES_PASSWORD` и
   `JWT_SECRET`, настоящий SMTP и согласованный `PUBLIC_BASE_URL`.
3. `APP_ROOT_PATH` равен внешнему URL-префиксу (например `/office-desk-gear`),
   либо пустой строке при размещении на собственном домене. Backend внутри
   контейнера продолжает обслуживать `/api/v1`, `/health/ready` и `/docs`.
4. В существующую HTTPS-секцию Caddy добавить `Caddyfile.shared.snippet`, а
   прежний `reverse_proxy` и его `request_body` оставить внутри отдельного
   fallback `handle`. Это сохраняет исходный маршрут `maskarad` и его лимит
   тела 6 MB; собственный маршрут получает 8 MB для изображений в base64.
   Сохранить резервную копию, проверить `caddy validate`, затем сделать reload
   без перезапуска контейнера. Для nginx оставлен отдельный пример.

```sh
cd /opt/projects/office_desk_gear
docker compose --project-name office-desk-gear --env-file .env.server -f deploy/compose.shared.yaml config --quiet
docker compose --project-name office-desk-gear --env-file .env.server -f deploy/compose.shared.yaml up -d --build
curl --fail http://127.0.0.1:8011/health/ready
```

Startup выполняет Alembic, проверяет БД и SMTP-конфигурацию. Без настоящего SMTP
production не запускается: подтверждение почты и восстановление пароля нельзя
считать проверенными только по успешному `/health`. Мобильный APK должен быть
собран с фактическим публичным HTTPS URL, оканчивающимся на `/api/v1`.

На сервере с 2 GB RAM предусмотрены лимиты: БД 256 MB, API 384 MB, один worker,
ограниченные PostgreSQL-соединения и журналы. БД использует отдельную внутреннюю
сеть. Фотографии остаются защищены bearer-токеном; клиент добавляет публичный префикс
к сохранённым относительным путям и не передаёт токен другим проектам хоста.
Документация FastAPI учитывает `APP_ROOT_PATH`; см.
[официальное описание прокси](https://fastapi.tiangolo.com/advanced/behind-a-proxy/).

## Загрузка

На рабочем компьютере `python scripts/package_server.py` собирает проверяемый
архив только серверного кода и deployment-файлов. `.env`, SSH-ключи, пароли,
локальная БД/вложения, мобильный клиент и тестовые артефакты в него не входят.
Архив сопровождается SHA-256 и перечнем файлов с их хешами.

Перед обновлением существующего размещения следует сделать резервную копию
его конфигурации, БД и вложений; тома не удалять. При первом размещении создать
только каталог проекта. Администратора создать через `server.cli create-admin`
в контейнере API; демонстрационные учётные записи в production не добавляются.
