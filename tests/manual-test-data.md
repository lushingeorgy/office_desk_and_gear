# Данные для ручной проверки

Эти аккаунты создаются командой `seed-demo` в локальной development-базе. Данные не добавлены на удалённый сервер. Укажите отдельную локальную PostgreSQL-базу в `.env`, выполните миграции и загрузите демонстрационные записи:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m server.cli seed-demo
.\.venv\Scripts\python.exe -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

В другом окне PowerShell запустите клиент с этим локальным сервером:

```powershell
$env:DSH_API_URL = "http://127.0.0.1:8000/api/v1"
.\.venv\Scripts\python.exe main.py
```

Команда `seed-demo` сохраняет уже существующие аккаунты и пароли. Для указанных ниже ID оборудования нужна новая база без ранее созданной техники. В существующей базе получите QR для нужного устройства из реестра под IT-администратором.

| Должность | Почта | Пароль |
| --- | --- | --- |
| Сотрудник | `employee@company.ru` | `password123` |
| Офис-менеджер | `office@company.ru` | `password123` |
| IT-администратор | `it@company.ru` | `password123` |

QR-изображения для сканирования находятся в `tests/fixtures/manual-qr/`. Они открывают ноутбук №1 и монитор №2 из стандартного наполнения новой базы. Полные записи и содержимое QR-кодов находятся в `tests/manual-test-data.json`.

Монитор №2 на первом рабочем месте:

В форме заявки сотрудника ноутбук доступен сразу. Монитор появится после создания текущей брони на его стол. IT-администратор выбирает технику из всего реестра.

Вручную проверьте вход под каждой должностью, просмотр профиля и недоступность изменения должности, смену пароля с текущим паролем без почтового кода, создание заявки из вкладки «Заявки» с выбором оборудования и сканирование обоих QR-кодов в портретной ориентации.
